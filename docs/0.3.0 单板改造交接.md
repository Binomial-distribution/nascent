# 0.3.0 单板改造交接

这次改造去掉了行空板 UNIHIKER K10 与 HW504 摇杆，手机直连玩具侧 ESP32-S3。
协议随之升到 `0.3.0-demo`，**是破坏性变更**。

固件、协议、控制端与 Android 壳的改动已经落地。这个文件写给**没有参与这次
改造、但在同一个仓库里改别的东西的人**：告诉你哪些前提变了、你那一侧要不要跟、
以及哪些约定现在起不能单方面改。

前后端目前由不同的人在并行修改，所以本文对每一处待办都给出了具体文件与行号，
请在**你自己的分支**里改，不要等别人替你改。

## 新拓扑

```
手机（网站 / PWA / Android 壳）
   ├── BLE GATT（默认通道）
   └── WiFi WebSocket（备用通道）      ← 同一时刻只开一条
        ↓
ESP32-S3-N16R8 玩具侧（唯一一块板）
   ├── BOOT 键 GPIO0（短按 = 本地急停；长按 2s = 解除停机闩锁）
   ├── DHT11 / MPU6050 / FSR402（传感）
   ├── WS2812B ×8（灯语，档位 = 点亮颗数）
   └── GPIO7 → AO3400A 低边 N-MOS → 并联原产品按键触点 → 原产品控制板
```

中间没有别的板子了。手机连的就是玩具本身。

## 三条衔接面各自的权威文档

| 衔接面 | 文档 | 这次是否变了 |
|---|---|---|
| App ↔ 玩具（默认） | [`protocol/ble_gatt.md`](../protocol/ble_gatt.md) | 变了：宿主从 K10 换成玩具侧 |
| App ↔ 玩具（备用） | [`protocol/wifi_ws.md`](../protocol/wifi_ws.md) | 新增 |
| App ↔ 后端 | [`protocol/http_api.md`](../protocol/http_api.md) | 新增文档，接口形状**没变** |

跨端字段一律只改 `protocol/contract.yaml`，然后跑 `python3 protocol/tools/gen.py`。
不要手改 `protocol/generated/`、`protocol/schemas/`，也不要手改各端包内的协议副本
（`software/app/js/protocol.js`、`software/backend/app/protocol.py`）。

## 协议破坏性变更清单

删除：

| 项 | 原属 | 说明 |
|---|---|---|
| `joy_edge` 枚举 | 顶层 | 摇杆推到边缘的方向，无对应物了 |
| `set_joystick` | `cmd` 枚举 | 同上 |
| `BleUplink.joy_edge` | 上行 | 同上 |
| `BleDownlink.enabled` / `hold_ramp` | 下行 | 都只服务摇杆长推加档 |
| `JOY_EDGE_HOLD_MS` / `JOY_HOLD_RAMP_MS` / `JOY_DEADZONE` | 常量 | 同上 |
| `pair` / `ack` / `heartbeat` 帧 | 线上格式 | 只有 ESP-NOW 板间链路需要配对、应答与心跳；`frame_type` 从五项收缩为 `[telemetry, command]` |
| `protocol/espnow_frame.md` | 文档 | ESP-NOW 整体移除，新增 [`wifi_ws.md`](../protocol/wifi_ws.md) |

新增：

| 项 | 值 | 用途 |
|---|---|---|
| `BOOT_KEY_DEBOUNCE_MS` | 40 | BOOT 键消抖 |
| `BOOT_STOP_MAX_MS` | 600 | 松手早于此 = 短按 = 急停 |
| `BOOT_RESUME_HOLD_MS` | 2000 | 按住超过此 = 解除闩锁 |
| `TRANSPORT_IDLE_SWITCH_MS` | 20000 | 当前通道空闲多久后允许切换 |
| `wifi:` 段 | `ws_port: 81`、`ws_path: "/nl"`、`mdns_host: "nascent"` | WebSocket 备用通道 |

语义变了但结构保留的：

`wire_header` 与 `wire_frames` 还在契约里，但**不再是板间线上格式**。0.3.0 起
它们描述的是玩具侧固件的内部表示（传输层 JSON ⇄ `nl_command_t` / `nl_telemetry_t`）。
所以 `generated/nascent_protocol.h` 里那些 packed struct 现在只在一块板内部使用，
250 字节的 ESP-NOW 载荷上限断言也随之删除。`command.flags` 原来的
`bit0 joystick_enabled` / `bit1 hold_ramp` 现在是保留位。

### 最容易踩的一个坑：`resume` 的线序前移了

`cmd` 枚举删掉的是**中间**一项，所以后面的值整体前移：

```
0.2.0:  stop=0  set_mode=1  set_level=2  set_pattern=3  set_led=4  set_joystick=5  resume=6
0.3.0:  stop=0  set_mode=1  set_level=2  set_pattern=3  set_led=4                  resume=5
```

线上传的是**字符串**枚举名，所以 JSON 层面不受影响。但任何地方如果把数值
硬编码过（日志、测试夹具、临时脚本、手搓的调试帧），旧的 `6` 现在什么都不是，
而旧的 `5` 会被解成 `resume`。**请搜一遍自己那一侧有没有裸的枚举数值。**

## 各端要做什么

### 前端（`software/app/`）—— 已改，但有你需要知道的

`ble.js` 拆成了四个模块：

| 文件 | 职责 |
|---|---|
| `transport.js` | 选路：决定走 BLE 还是 WiFi，持有通道与玩具地址 |
| `ble.js` | Web Bluetooth 与 Android 原生桥 |
| `ws.js` | WiFi WebSocket |
| `channel.js` | 两条通道的共同部分：协议主版本门控、上行解析、监听者管理 |

拆出 `channel.js` 而不是让两条通道各写一份，理由和固件侧 `downlink_gate` 一样：
版本门控和上行解析是两条通道都必须做对的事，抄成两份之后只改了一边的修补
就会让另一条变成弱点。

**你需要注意的三点：**

1. `session.js` 导出的 `ble` **改名成了 `link`**。如果你有未提交的代码
   `import { ble } from "./session.js"`，改成 `link`。改名是因为"蓝牙"不再等于
   "设备连接"。
2. **发指令仍然只有一个入口 `sendCommand()`**，它会先过安全总督。不要直接调
   `link.send()`——绕过去就等于绕过总督。换传输不改变这条规则。
3. `sw.js` 的缓存名升到了 `nascent-shell-v2` 并加进了三个新模块。**以后新增
   任何 `js/` 模块，都要同时加进这个列表并升版本号**，否则老客户端会拿着一份
   缺文件的缓存，`import` 直接 404。

### 后端（`software/backend/`）—— 只剩两处源码注释

接口形状、模型、路由**一个都没变**。`app/protocol.py` 已经由 `gen.py` 重新生成为
`0.3.0-demo`，`CloudSummary` / `CloudActionEnvelope` 字段没有增删。
`README.md` 已经改过：K10 那一层换成了玩具侧 `DownlinkGate`，过滤仍是四层
（云端审核 → 浏览器总督 → DownlinkGate → SafetyGovernor），不是少了一层。

还剩 **2 处源码注释**描述的是旧架构。这两个 `.py` 由后端维护者改，避免覆盖
未提交的修改：

| 文件 | 行 | 现在写的 | 应该改成 |
|---|---|---|---|
| `app/main.py` | 6 | 「再由 K10 和玩具侧固件各自的规则过滤」 | 「再由玩具侧固件的下行拒绝规则与安全总督各判一次」 |
| `app/routers/session.py` | 16 | 「K10 和玩具侧固件还会各判一次」 | 「玩具侧固件的下行拒绝规则与安全总督还会各判一次」 |

顺带一件值得你决定的事：`GET /v1/persona` 返回的 `Persona` 是这条链路上
**唯一不由 `contract.yaml` 生成**的结构，手写在 `app/routers/persona.py`。
前端直接消费 `res.json()`、不校验字段，所以你单方面改它不会有任何东西报错，
前端会安静地显示空白。骨架期先靠 [`protocol/http_api.md`](../protocol/http_api.md)
约束；人设一旦要落库或字段变多，建议把它收进 `contract.yaml`。

### 固件（`hardware/toy-sidecar/`）—— 已改

新增 `transport.h`、`ble_peripheral.{h,cpp}`、`wifi_ws.{h,cpp}`、
`downlink_gate.{h,cpp}`、`uplink_json.{h,cpp}`、`boot_key.{h,cpp}`；
删除 `espnow_link.{h,cpp}`。`platformio.ini` 加了
`board_build.partitions = huge_app.csv`。

WiFi 凭据放在 gitignored 的 `include/local_config.h`（有 `.example` 模板）。
**没有这个文件时 WiFi 通道不启用，只有 BLE**，这是刻意的：不能让缺配置变成
"以为在跑 WiFi 其实没跑"。

### Android 壳（`software/app-android/`）—— 已改

只改了用户可见文案（「行空板」→「玩具」）。`BleBridge` 的扫描过滤器本来就吃
页面传来的 `deviceName`，所以广播名从 `Nascent-K10` 改成 `Nascent-Toy`
没牵动它一行逻辑。这正是当初"UUID 与设备名一律由页面传入、原生侧不抄契约"
换来的好处。

## 不能单方面改的安全不变量

这几条跨越前端、后端、固件三侧。**任何一侧单方面放松它，另外两侧都无法补救**，
所以改动前必须先在 [`docs/architecture/产品架构.md`](architecture/产品架构.md)
里改结论，并让三侧维护者都看到。

1. **停机闩锁只能由物理 BOOT 键长按 2 秒解除。** 固件的
   `SafetyGovernor::onCommand` 里**没有** `NL_CMD_RESUME` 分支，
   `clearLatch()` 全工程只有 `main.cpp` 的 `pollBootKey()` 一处调用。
   传输层也各自拒绝 `resume` 并记 `bad_cmd`，但那只是给用户的反馈、不是防线——
   **过滤会漏，不存在的代码路径不会漏**。不要"顺手"给它加回一个入口。

   为什么双板时期可以有这个分支：那时指令只可能来自 K10，而 K10 只在用户
   按下板载 A+B 双键时才发 `resume`，物理确认仍在。手机直连之后这个前提消失，
   留着它就等于让手机能远程解除用户刚按下的停机。

2. **手机断连即归零。** 0.3.0 之前 K10 断连不停机是合理的——K10 上还有摇杆
   和屏可以本地控。现在玩具侧唯一的本地入口是 BOOT 键，**只能停不能开**，
   所以断连不能保持输出。

3. **越界指令直接丢弃，不钳位。** 云端审核、前端总督、固件下行门三处一致。
   把 99 悄悄改成 8 去执行，比拒绝危险得多。

4. **玩具侧不驱动电机**，只并联原产品按键触点。停机不能由 App 或云端解除。

5. **发指令必须过安全总督**（前端 `sendCommand()`）。新增任何控制入口都要走它。

## 联调步骤

```bash
# 1. 协议：改完 contract.yaml 一定要重新生成，三端副本同源
cd protocol && python3 tools/gen.py

# 2. 固件
cd hardware/toy-sidecar && pio run -t upload && pio device monitor

# 3. 后端（同时托管网站）
cd software/backend && source .venv/bin/activate && uvicorn app.main:app --reload

# 4. 前端契约测试
cd software/app && node tests/run.mjs
```

连设备时的通道选择在「设置 → 设备 → 通道」。默认蓝牙；选 WiFi 时会多出
一行「玩具地址」，填 `192.168.1.20` 或 `nascent.local` 均可，端口与路径由契约
补全。地址只存在内存里，刷新页面需要重填——与本应用其余部分一致
（心绪、笔记、收藏都只保存在本次运行内），不为一个备用通道的便利开新的
持久化面。

## 已知限制，请不要当成 bug 去"修"

**手机浏览器上两条设备通道不可能同时可用。** Web Bluetooth 要求安全上下文，
手机访问 `http://<PC 局域网 IP>:8000` 不是安全上下文，蓝牙不可用；反过来
一旦站点上了 HTTPS，玩具侧只有 `ws://`，WiFi 会被按混合内容拦掉。Android 壳
没有这个矛盾（`usesCleartextTraffic="true"` + 原生 GATT 桥），所以 **WiFi 备用
通道以 Android 壳与桌面 Chrome 为主要验证路径**。

`ws.js` 在 HTTPS 页面下会**提前**报错说明原因，而不是让请求沉默失败——那个
拦截发生在 JS 之外，浏览器给的报错毫无线索。

**去掉摇杆也去掉了"断网仍能换档"这条能力**，现在只剩原产品实体按键。这推翻了
架构文档里原有的「离线换档」取舍，已在 `docs/architecture/产品架构.md` 改写。

**去掉 K10 也去掉了那块 2.8 寸屏**，本地反馈只剩 WS2812B×8（档位 = 点亮颗数）
与串口日志。

## 待认领

- **上板验收**（需要真机，尚未做）：停机 < 300ms、断连归零、闩锁只能由 BOOT 键
  解除、上电瞬间不误发按键、WiFi 备用通道也能停机。BOOT 键是 GPIO0 strapping
  脚，上电时序需要在真机上确认。
- **后端那 2 处过期注释**（见上表：`app/main.py`、`app/routers/session.py`）。注释只改了架构描述，没有改逻辑，留给后端维护者。
- 后端鉴权：目前所有接口都是裸的，暴露到公网前必须补，这是上线阻塞项。
- `hardware/toy-sidecar/` 目录名里的 "sidecar" 是双板时期留下的，现在它是唯一
  一块板。暂不改名以免牵动所有路径引用，但知道这件事。
