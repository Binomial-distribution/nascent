# Nascent Love B 层完整软件实施计划 B3.0

> 来源：本机与 GPT Codex 同步的 B 层实施计划原文（2026-08-28）。
> 产品权威规格见 [`docs/architecture/B层完整版技术文稿-双模型与偏好闭环.md`](../architecture/B层完整版技术文稿-双模型与偏好闭环.md)；当前落地状态见 [`app-heart-intimacy-plan.md`](app-heart-intimacy-plan.md)。

## Summary

B 层建设为三个平行模块：`情景漫游`、`我的节奏`、`身体笔记`。核心采用 Chat 9B 与 Control 9B 双模型并行，融合压力、产品表面温度和小米手环心率，分别完成对话陪伴、有限自动适配、身心参考记录和用户偏好学习。

目标是帮助用户找到更合适的节奏并接近自己认可的 climax；产品不宣称“检测高潮”或诊断健康，统一输出“可能的高响应区间”和“安全与身心参考”，最终含义由用户确认。

## 页面与交互

- `亲密时刻 → 情景漫游`：三个同级按钮为 `选择已有人设`、`定义人设`、`对话创建人设`。
- `选择已有人设 → 人设列表 → 情景聊天`；点击人设直接进入独立的微信式聊天页。
- `定义人设 → 结构化表单 → 保存 → 情景聊天`；可选择温柔、强势、SM 风格、安静、玩心、说话频率和允许的 Skill。
- `对话创建人设 → 创建助手对话 → 预览并确认 → 情景聊天`；创建对话和实际使用对话必须是不同页面。
- `亲密时刻 → 我的节奏`：只保留 `自由档位` 和 `失控模式`，不出现人设、情景或聊天入口。
- `自由档位 → 控制页`：八档 Slider，仅松手发送；档位 0 为停止，固定大停止按钮始终可见。
- `失控模式 → 时间配置与健康提示 → 二次确认 → 独立使用页`；AI 不能延长计时或恢复停止状态。
- `身体笔记 → 记录列表 → 单次详情`；详情上方是本次记录，下方是近期图表与总结，底部只有一个 `了解自己` 对话入口。
- 所有主要操作放在屏幕下半区，触控高度至少 48dp，停止按钮至少 56dp；选择页与使用页严格分层。

情景聊天采用微信式布局：顶部人设与连接状态，中部消息，底部固定停止、按住说话、文字输入和更多。聊天上方常驻一条三传感器摘要，点击后打开详情抽屉，展示：

`传感器 → 聚合趋势 → Agent 判断 → Policy 结果 → Governor 结果 → 实际设备状态`

## 双模型、语音与 Waifu

- `nascent-chat-9b`：人设对话、情景推进、心理反馈、身体笔记解释和记忆候选。
- `nascent-control-9b`：读取脱敏后的三传感器趋势、当前档位和模板边界，输出 `hold / recommend / ask`。
- 两个别名初期均指向 `Qwen/Qwen3.5-9B`，使用独立 Prompt、Schema、超时和上下文，后续可拆成两个实例。
- 每轮重新组装系统规则、人设、模板、最近六轮、滚动摘要、已授权记忆、传感器摘要和同意状态；用户文本不能覆盖系统安全规则。
- 语音默认按住说话：本地 VAD、可替换 ASR、流式 Chat 输出、分句 TTS；文字输入始终可用。
- Waifu 插件只消费台词、表情、动作和可打断状态，不读取原始传感器、记忆、音频或设备控制接口。
- 延迟目标：ASR 首字低于 900ms、Chat 首段低于 1.5s、Control 低于 1s；停止低于 500ms并完全绕过模型。

## 三传感器融合与体验辅助

新增强类型 `SensorSnapshot`，替换松散的 `sensor_context`：

- 压力：接触质量、左右压力相对值、节律、连续时间、上升/平稳/变化/下降和缺失率。
- 温感：只记录产品表面/接触温度、相对变化、变化速度、舒适区状态和数据质量，不解释为核心体温。
- 心率：Android Health Connect 读取小米手环同步数据，包含会话前参考值、变化量、趋势、覆盖率、来源和新鲜度。
- 原始压力、温度和 BPM 曲线保存在本地加密记录；发送给模型的只有 5–10 秒聚合特征。

确定性融合器输出 `ResponseAssessment`：

- 阶段为 `unknown / settling / engaged / rising / sustained / recovery`。
- 至少两种有效传感趋势同向，且没有停止、不适、减速等负面反馈，才产生“可能的高响应区间”。
- 心率、压力或温感任何单一信号都不能判断 climax、同意或偏好。
- 区间只能标为 `candidate`；用户选择“这段很有感觉”后才变为 `confirmed` 并允许进入偏好学习。
- 接近高响应区间时默认优先保持稳定节奏，避免模型持续加档导致越过用户舒适点。

用户选择“有限自动适配”后，只在情景漫游单次会话中生效：

- 会话开始必须显式开启，退出会话后授权失效。
- 自动 Skill 仅允许 `rhythm_segment` 和 `set_pattern`，全部经过 Policy、`Governor` 和 `senderProvider(..., automatic: true)`。
- 每次最多变化一档，至少保持 30 秒，自动变化冷却 45 秒；7、8 档始终需要用户再次点击确认。
- 至少两种传感器质量有效、链路正常、同意状态有效且无安全事件时才允许自动执行。
- “我的节奏”自由档位始终手动；失控模式只按固件计时，不接受 Agent 自动调档。

## 健康与安全参考

新增确定性 `WellnessAssessment`，状态为 `clear / check_in / pause_recommended / stop_required`：

- 固件 NTC 过温、急停、安全词和链路安全规则直接触发停止，不等待 AI。
- 压力持续时间过长或节律突然变化只触发询问、休息或调整姿势提示，不诊断身体损伤。
- 心率相对参考值明显变化但没有用户不适时只做温和确认；心率单独不能触发自动停止或健康结论。
- 用户报告胸闷、头晕、疼痛、麻木或明显不适时停止自动 Skill，并提示暂停使用和根据情况寻求专业帮助。
- DHT11 环境温度不能作为接触面过温熔断数据；只有量产接触 NTC 和固件规则属于硬安全通道。

## 身体笔记、偏好与记忆

单次记录固定包含：会话概览、档位时间线、压力节律、表面温感、心率图和覆盖率、可能高响应区间、结束原因、数据质量、用户主观反馈和可编辑总结。

总结分为三段：

- `生理参考`：只陈述压力、温感、心率和时间上的可观测变化。
- `心理体验`：来自使用前后心绪、舒适度、掌控感、风格标签、最有感觉片段和用户原话。
- `身心关联`：描述哪些变化同时出现，不宣称因果，并明确“不代表固定偏好”。

详情页下方比较最近 5 次有效记录；`了解自己` 进入独立 Chat 页，一次读取当前记录和最多 5 次近期记录，并在页面显示实际数据来源。整段对话默认不持久化，只有用户点击“保存这条发现”才写入可编辑、可删除笔记。

IRPI 权重使用：明确反馈 `0.45`、主动行为 `0.25`、压力 `0.12`、温感 `0.08`、心率 `0.05`、情境匹配 `0.05`。传感器只提供辅助证据，偏好写入必须有用户确认；安全事件、停止、不适或撤回同意时拒绝学习。

后端保存人设、模板、聚合会话趋势、控制决策理由、已确认总结、记忆和偏好；原始传感器默认只存本地 SQLCipher。删除会话时级联删除曲线、摘要、高响应候选、对话发现和偏好观察；删除人设时删除其关系记忆。检索层先写 tombstone，防止已删除数据被缓存重新召回。
