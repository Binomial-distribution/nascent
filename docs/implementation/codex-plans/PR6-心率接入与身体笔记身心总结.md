# PR #6 完善、心率接入与身体笔记身心总结计划

> 归档来源：本机 GPT Codex 实施计划（2026-08-28）。历史方案，不以本文件覆盖 B3.0 权威规格。心率与 Health Connect 拆后续短 PR。

## Summary

在现有分支 `feat/body-notes-insight` 上完善 Draft PR #6：修复已有审查问题，接入 Android Health Connect 读取小米手环 7 同步的心率，把心率加入双模型上下文、身体笔记和偏好候选流程，并将身体笔记调整为：

`记录列表 → 单次详情（上方）→ 近期趋势与总结（下方）→ 单一“了解自己”入口`

心率只作为参考性生理趋势。产品不宣称识别情绪或检测高潮，统一使用“可能的生理峰值区间”；心理含义必须来自用户自述、确认或对话。

## Key Changes

### PR #6 审查修复

- Skill 统一为 `rhythm_segment`、`set_pattern`；`hold_current` 只属于 Control 决策。
- 双模型别名统一为 `nascent-chat-9b` 和 `nascent-control-9b`，初期均映射 `Qwen/Qwen3.5-9B`。
- 修复身体笔记异步加载覆盖本地删除结果的问题，使用请求版本号和本地删除 tombstone。
- 允许“这不代表固定偏好”等安全提示，只拦截“证明你喜欢”“这是固定偏好”等确定性断言。
- Control 的 `hold` 保留 `reason_codes`；未知模式降级到安全默认 UI。
- 校验记忆查询 `limit=1..20`，统一文档和代码中的删除路由。
- 清理旧 `nascent-shell-*` Service Worker 缓存，并在 CI 安装 `pytest-asyncio`。

### Android 心率接入

- 在 `software/app-android` 增加 Health Connect 适配器和 WebView JS Bridge：
  - 检查 Health Connect 可用性。
  - 单独请求 `READ_HEART_RATE` 权限。
  - 按会话时间范围读取 `HeartRateRecord`。
  - 返回数据来源、采样数、覆盖率、最后采样时间和降级原因。
- 会话开始时读取前 5 分钟中位数作为“会话前参考值”；有效样本不足时不计算心率变化量。
- 使用期间每 15 秒机会性刷新；只有最新样本不超过 30 秒才允许进入实时 AI 摘要，否则标为“等待同步”。
- 会话结束、App 恢复前台和打开记录详情时重新读取完整区间，允许延迟同步后更新记录。
- 权限拒绝、手环未同步或没有数据时，产品继续正常运行，身体笔记显示“本次无可用心率记录”。
- 本轮不逆向连接小米手环 BLE，不依赖 Zepp 私有协议；后续可以替换为官方数据源适配器。

### 心率数据与 AI 边界

- 保留协议现有 `SessionCurves.hr_1hz` 和 `CloudSummary.hr_trend`。
- 为云端摘要补充可空的 `hr_quality`、`hr_delta_bpm`、`hr_freshness_ms`，升级契约版本并重新生成三端产物。
- 原始 BPM 数组只用于本地归档和图表，不发送给 Chat 9B 或 Control 9B。
- 模型只接收趋势、相对参考值变化、覆盖率、时间区间和数据质量。
- Control 9B 不得因为心率单独加档、减档、停止或写入偏好；任何动作仍须经过 `Governor`。
- Chat 9B 可以询问“这一段对你意味着什么”，不得把心率直接解释为兴奋、焦虑、高潮、同意或健康异常。

“可能的生理峰值区间”仅在以下条件同时满足时生成：

- 心率数据质量有效，且存在会话前参考值。
- 30 秒滚动中位数处于本次会话较高区间，并比参考值高至少 10 BPM。
- 同一时间前后 30 秒内至少存在压力节律、温感变化或用户主动标记之一。
- UI 只显示候选区间，并让用户选择“这段很有感觉 / 不是 / 不确定”。

未经用户确认的候选区间不能写入长期偏好。

### 身体笔记内容与总结

单次记录详情从上到下固定为：

1. **本次概览**：日期、时长、模式、人设、最高档位、结束原因、数据完整度。
2. **生理参考**：表面温感、接触压力、心率范围、相对参考值变化、覆盖率和数据来源。
3. **过程时间线**：档位、压力、温度和心率的对齐图表；心率缺失时图表保留空段，不插值伪造。
4. **可能的生理峰值区间**：显示时间、共同出现的信号和用户确认状态，不显示“高潮概率”。
5. **心理体验**：使用前后心绪、舒适度、掌控感、互动风格标签、最有感觉的片段和用户原话。
6. **综合总结**：分别展示“身体发生了什么”“你如何描述感受”“两者可能同时出现在哪里”。
7. **近期回看**：在同一详情页下方比较最近 5 次有效记录，包括时长、心率覆盖、趋势、舒适度和确认过的偏好。
8. **了解自己**：页面底部只有一个入口，进入独立的微信式对话页。

总结采用“确定性统计 + Chat 9B 表达”两段生成：

- 程序先生成可核验的传感器事实、缺失信息和时间关联。
- Chat 9B 只能根据这些聚合事实以及用户自述生成非评判总结。
- 没有用户反馈时，心理部分显示“本次尚未记录主观感受”，并提供简短引导问题。
- 总结必须包含“心率也可能受到活动、呼吸和当时状态影响，不代表固定偏好”。
- AI 草稿允许编辑；只有用户确认后才保存为身体笔记或偏好候选。

### 偏好学习与删除

- IRPI 权重调整为：明确反馈 `0.45`、主动行为 `0.25`、压力 `0.12`、温度 `0.08`、心率 `0.05`、情境匹配 `0.05`。
- 心率分量只有在数据有效、存在多信号支持且用户明确确认后才参与计算。
- 安全事件、撤回同意、停止、不适、数据过期或大量缺失时拒绝该次偏好学习。
- 删除一次记录时级联删除本地心率曲线、聚合结果、候选峰值、AI 总结、保存的发现和相关偏好观察。
- 删除人设时继续删除该人设的关系记忆和偏好快照，不删除用户主动保留的匿名身体记录。
- 本 PR 保留可替换的内存后端用于联调；生产 PostgreSQL、账号归属和删除审计作为明确后续任务，原始心率默认不上传。

### 情景漫游文档同步

技术文档固定情景漫游三层入口：

- `选择已有人设 → 人设列表 → 独立情景聊天`
- `定义人设 → 结构化表单 → 保存后进入情景聊天`
- `对话创建人设 → 创建对话 → 用户确认 → 独立情景聊天`

人设创建和实际使用不能共用页面；完整情景 UI 留给后续短 PR，本 PR 不把情景入口放进“我的节奏”。

## Assumptions

- 本轮采用用户确认的 Health Connect 方案和“辅助证据”偏好策略。
- 小米手环 7 是否及时向 Health Connect 写入数据取决于用户设备环境，因此实时心率属于机会性能力，不能作为安全功能依赖。
- “生理意义”表示可观测的身体趋势和时间关联；“心理意义”只来自用户自述及其确认。
- 产品界面不使用“高潮检测、情绪识别、性功能评分或健康异常”等表述。
