## Key Changes

### 身体笔记

- 保持三级结构：`记录列表 → 记录详情 → 微信式了解自己对话`。
- 记录详情改为单页纵向布局：
  - 顶部展示本次日期、模式、时长、数据质量和事实摘要。
  - 接着展示本次档位、压力和温感可视化。
  - 下方直接展示最近最多 5 次有效记录的对比图表和聚合总结。
  - 数据不足时显示明确说明，不推断偏好。
- 移除“只看这一次”和“参考近期记录”两个固定按钮及额外范围选择弹窗。
- 页面底部只保留一个“了解自己”入口。
- 点击入口即授权 Chat 9B 读取页面上明确列出的本次记录和近期记录；聊天页持续显示具体来源。
- 修复启动竞态：
  - 有后端请求能力时，加载完成前状态保持“未确定”。
  - 加载或后端状态未确定时，删除、保存发现和发起洞察等修改操作全部失败关闭。
  - UI 同步禁用相关按钮并显示加载状态。
  - 纯静态演示明确标记为离线状态，仍允许仅修改内存数据。
  - 后端加载完成后不能覆盖加载期间的本地操作，也不能让已删除记录复活。
- 所有模式名称统一通过安全回退获取，未知模式按 `free` 展示，避免 `MODE_UI[item.mode]` 抛出异常。

### B 层契约与后端

- 统一 Skill 契约：
  - 模板和 Chat Skill 使用 `rhythm_segment`、`set_pattern`。
  - `hold_current` 只属于 Control 9B 的控制决策，不作为模板硬件 Skill。
  - 文档不再把设备协议命令 `set_level` 当作 Agent Skill。
- 统一双模型名称：
  - `nascent-chat-9b` 是 Chat 逻辑角色别名。
  - `nascent-control-9b` 是 Control 逻辑角色别名。
  - 两者初期均可映射到供应商模型 `Qwen/Qwen3.5-9B`，但使用独立配置和超时。
  - `nascent-realtime-9b` 标记为已废弃的旧口径，不再用于新流程。
- 修复 `generate_control()`：
  - `hold` 决策保留模型原有 `reason_codes`。
  - `hold` 携带的 Skill、档位、Pattern 等建议字段全部清空。
  - 只有 `recommend` 决策才检查模板 Skill 白名单。
  - 不允许的推荐降级为 `hold + skill_not_allowed`。
  - 所有结果继续强制 `action=null`，不能直接生成设备命令。
- 重构身体洞察过滤：
  - 保留设备控制、医疗诊断和确定性偏好断言的禁止规则。
  - 删除对“固定偏好”的宽泛子串封禁。
  - 禁止“说明你喜欢”“证明你”“你一定”等确定性断言。
  - 允许“不代表固定偏好”等否定性安全说明。
  - 本地安全回退也必须经过 `BodyInsightModelOutput` 契约验证，不能绕过校验器。
- `/v1/agent/memory` 的 `limit` 使用 FastAPI 参数约束为 `1..20`，非法值返回 `422`；内存 Provider 再做一次防御性限制。

### 情景漫游文档层级

情景漫游入口页明确只有三个并列按钮：

1. `选择已有人设`
   展示以前创建或保存的人设；点击某个人设直接进入独立情景聊天页。
2. `定义人设`
   使用结构化表单设置名称、风格、语气和允许的 Skill；确认创建后直接进入情景聊天页。
3. `对话创建人设`
   进入专门的人设创建对话；生成并确认人设后，再跳转到真正的情景聊天页。

人设创建对话与实际情景使用必须是不同页面和路由。实际使用页采用类似微信的消息气泡界面，包含人设信息、连接状态、对话、语音入口和脱敏数据走向，但这部分 UI 编码留到后续独立短分支。

- `GET /v1/agent/memory?limit=`：仅接受 `1..20`。
