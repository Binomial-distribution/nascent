## 一、总体方案

**第一层「心绪」由四个开源参考拼装而成，每个只取其"骨架/组件/思路"，不整体复用：**

| **来源** | **取用范围** | **用于** |
|-|-|-|
| moodiary（github.com/ZhuJHua/moodiary） | 本地优先数据架构、首页问候+历史流骨架、应用锁实现思路 | 首页结构、隐私架构对齐、设置页应用锁 |

## 三、每日卡片滑动实现（flutter_card_swiper）

### 3.1 依赖

```yaml
dependencies:
  flutter_card_swiper: ^latest
```

### 3.2 核心交互代码

```dart
CardSwiper(
  controller: cardController,
  cardsCount: todayCards.length,
  allowedSwipeDirection:
    AllowedSwipeDirection.only(left: true, right: true),
  onSwipe: (previousIndex, currentIndex, direction) {
    if (direction == CardSwiperDirection.right) {
      favoritesRepo.save(todayCards[previousIndex]); // 右滑=收藏
    } else {
      readLogRepo.markRead(todayCards[previousIndex]); // 左滑=已读
    }
    return true; // 允许滑动；返回false可拦截
  },
  onUndo: (previousIndex, currentIndex, direction) {
    readLogRepo.undo(previousIndex); // 误滑找回
    return true;
  },
  onTapDisabled: false, // 点击卡片本身触发展开长文，不触发滑动
)
```

### 3.3 设计要点

- 方向语义：右滑=收藏、左滑=已读跳过，点击=展开长文——手势与点击天然分工，不冲突
- CardSwiperController 同时驱动屏幕上的"收藏/跳过"实体按钮，照顾不习惯手势滑动的用户
- 每日卡片池：4大栏目（认识身体/安全与卫生/读懂信号/状态与生活）按算法轮换推荐+已读去重，安全与卫生栏目全量免费展示优先级最高
- 推荐红线：仍遵循"数据触发科普不做结论"原则——推荐逻辑只影响"哪张卡先出现"，卡片内容本身保持普适性

## 四、分享图生成实现（参考Prism模板思路）

### 4.1 依赖

```yaml
dependencies:
  share_plus: ^latest
```

### 4.2 核心实现：独立渲染Widget（安全设计核心）

**关键原则：分享图使用专用的ShareCardWidget渲染，该Widget的数据源只包含"卡片标题+正文+品牌水印"三项，物理上不接触用户情绪记录、昵称等任何隐私字段——从数据流层面杜绝隐私泄露，而非依赖事后打码。**

```dart
final boundary = shareKey.currentContext!.findRenderObject()
    as RenderRepaintBoundary;
final image = await boundary.toImage(pixelRatio: 3.0);
final pngBytes = await image.toByteData(format: ImageByteFormat.png);
await Share.shareXFiles([
  XFile.fromData(pngBytes!.buffer.asUint8List(),
    mimeType: "image/png")
]);
```

### 4.3 设计要点

- ShareCardWidget 只接受 {title, body, watermark} 三个字段作为构造参数，不引用任何用户数据Provider
- 报告类分享图（如年度回顾）默认全打码，用户可在分享前的预览页手动选择"露出程度"
- 水印统一为"来自 Nascent Love"，作为低成本获客的自然传播入口

## 五、Streak 打卡状态机（用于「21天认识自己」）

### 5.1 状态判断逻辑

```dart
void checkin(DateTime today) {
  final last = lastCheckinDate;
  if (isSameDay(last, today)) {
    return; // 今天已打卡
  } else if (isSameDay(last, today.subtract(Duration(days:1)))) {
    streak += 1; // 昨天打过，连续+1
  } else {
    streak = 1; // 断档，重新计数
  }
  longestStreak = max(longestStreak, streak);
  lastCheckinDate = today;
  save();
}
```

### 5.2 「21天认识自己」产品化设计

| **设计点** | **方案** |
|-|-|
| 内容编排 | 21张卡片非随机池，按周编排：第1周"认识身体"→第2周"读懂信号"→第3周"找到节奏"；每天解锁1张，读完即视为打卡 |
| 里程碑反馈 | 第3/7/14/21天弹出专属徽章+AI伴侣祝贺语，价值在"被看见"而非数字本身 |
| 防挫败机制（重点，区别于健身类App） | 断签不清零进度，只暂停streak计数；文案："休息了一天也没关系，我们继续"；提供每月1次"补签卡" |
| 权益划分 | 每周精选卡免费；完整21天系列为Nascent Love+订阅内容 |
| 留存触点 | 断签提醒走隐晦推送文案（如"今天的身体笔记在等你"），是自然的召回时机 |

## 六、本地数据结构（对齐moodiary的本地优先架构）

**存储：SQLCipher加密SQLite（与全案隐私架构一致），核心表：**

```text
mood_entry            -- 情绪打卡记录
  id, date, mood_emoji, note, created_at

card_read_log          -- 卡片阅读/收藏记录
  id, card_id, action(read|favorite), read_at

checkin_streak         -- 21天计划打卡状态
  plan_id, current_streak, longest_streak,
  last_checkin_date, paused_days, makeup_cards_left

knowledge_card         -- 知识卡片内容库（可远程更新，本地缓存）
  card_id, category, title, summary, body,
  reviewer, source_ref, is_free
```

数据边界：mood_entry与card_read_log属于行为偏好数据，本地记录、不用于外部广告画像、支持一键清空——与已定稿的隐私触点审计表对齐。
