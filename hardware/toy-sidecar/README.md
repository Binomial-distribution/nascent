# toy-sidecar —— 玩具侧协处理板

ESP32-S3-N16R8。负责采集、推断、点灯，以及通过 CD4066 并联原产品按键。

## 最重要的一条

**这块板不驱动电机。** 振动强度自始至终由原产品控制板决定，
本板能做的只是"替人按那个按钮"。这是硬件级的安全边界，
任何把 MOSFET 接到电机上的改动都等于推翻整个安全论证，不要做。

CD4066 的连续电流上限在 10mA 量级，接电机会直接烧片子。

## 接线

| 功能 | 引脚 | 备注 |
|---|---|---|
| DHT11 数据 | GPIO4 | 单总线，4.7k 上拉到 3V3 |
| WS2812B 数据 | GPIO6 | 8 颗，RMT 驱动 |
| CD4066 控制 | GPIO7 | HIGH = 闭合 = 等效按下原按键 |
| FSR402 左 | GPIO1 | ADC1_CH0，3V3—FSR—ADC—10k—GND |
| FSR402 右 | GPIO2 | ADC1_CH1，demo 未接（`TOY_HAS_FSR_R=0`） |
| MPU6050 SDA | GPIO8 | 400kHz |
| MPU6050 SCL | GPIO9 | |

改引脚要同步改 `include/config.h` 和这张表，两处不一致比两处都错更难查。

### CD4066 供电有个未决项

原按键触点的静态电压还没实测。两种情况处理方式不同：

- **Case A（触点是 3V3 逻辑）**：CD4066 直接吃 3V3，`NL_CD4066_CASE_A_3V3=1`，当前默认。
- **Case B（触点电压高于 3V3 或极性未知）**：必须换光耦隔离，不能硬接。

上电前先用万用表量原按键两端对地电压。量之前不要焊。

## 代码分工

| 文件 | 职责 |
|---|---|
| `main.cpp` | 12Hz 主循环，唯一的执行出口 |
| `safety.{h,cpp}` | 安全总督，**唯一**有权决定实际档位 |

通用驱动全部用 vendored 的社区库（见 [`../VENDOR.md`](../VENDOR.md)），
自己写的只有上表中的产品逻辑。

## 强度封顶是怎么实现的

协议 `NL_LEVEL_MAX = 8`，而原板有 9 档。**第 9 档在软件上不可达**，
这就是 90% 封顶在这套硬件上的物理落地方式，不是巧合也不是凑数。
不要为了"能不能再大一点"去改这个常量。

## 停机路径

`stop` 是唯一能穿过所有状态的指令。它的执行不在主循环里排队：
ESP-NOW 回调收到 `NL_CMD_STOP` 的那一行就直接调 `Cd4066::requestOffNow()`
和 `LedRing::renderSafewordNow()`，电机断电与灯变白是同一时刻发生的。

闩锁之后**不会自动恢复，也不能远程恢复**。唯一的解除途径是在 K10 上
同时长按板载 A、B 两键两秒，K10 才会发出 `resume`。App 写 `resume` 会被直接拒绝。

要求物理在场是刻意的：用户喊过停之后设备自己重新动起来，
是这个产品最坏的失败模式，不该由软件单方面决定。

## 烧录

```bash
pio run -e toy-sidecar -t upload
pio device monitor -b 115200
```

首次上电串口会打印本机 MAC，把它填进 k10-controller 的 `config.h`；
反过来把 K10 打印的 MAC 填进本工程的 `PEER_MAC_K10`。验证期不做动态配对。

## 还没做的

- 急停拉环的 GPIO 中断（`SafetyGovernor::onEstop` 接口已留好，没有接线）
- 电量采样，所以 `low_battery` 灯语目前没有触发源
- CD4066 的开环档位跟踪会随人工按实体按钮跑偏，`resync()` 留了接口但还没有触发条件
