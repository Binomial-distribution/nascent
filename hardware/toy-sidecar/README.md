# toy-sidecar —— 玩具侧主板

ESP32-S3-N16R8。负责采集、推断、点灯，通过 AO3400A 低边 N-MOS 并联原产品按键，
并作为手机的 BLE GATT 外设。

协议 0.3.0 起这是 demo 里**唯一**一块板：行空板 K10 与 HW504 摇杆已经删除，
手机直连本板。名字里的 "sidecar" 是双板时期留下的，暂不改目录名以免牵动所有路径引用。

## 最重要的一条

**这块板不驱动电机。** 振动强度自始至终由原产品控制板决定，
本板能做的只是"替人按那个按钮"。这是硬件级的安全边界，
任何把这条支路接到电机上、或者拆掉下面那颗 10kΩ 的改动，
都等于推翻整个安全论证，不要做。

这条边界不只是纪律，它有硬件兜底：按键支路的漏极串了 **10kΩ**，
整条支路的电流被封在 **0.37mA**（3.7V / 10kΩ），物理上带不动任何电机。
AO3400A 本体能过 5.7A，所以那颗电阻是安全论证的一部分，不是可选件——
拆掉它，"不驱动电机"就从物理事实退化成一句口头承诺。

## 接线

| 功能 | 引脚 | 备注 |
|---|---|---|
| DHT11 数据 | GPIO4 | 单总线，4.7k 上拉到 3V3 |
| WS2812B 数据 | GPIO6 | 8 颗，RMT 驱动 |
| AO3400A 栅极 | GPIO7 | HIGH = 导通 = 等效按下原按键；串 1k，栅极 47k 下拉 |
| FSR402 左 | GPIO1 | ADC1_CH0，3V3—FSR—ADC—10k—GND |
| FSR402 右 | GPIO2 | ADC1_CH1，demo 未接（`TOY_HAS_FSR_R=0`） |
| MPU6050 SDA | GPIO8 | 100kHz；内部上拉；同时扫 0x68/0x69 |
| MPU6050 SCL | GPIO9 | |
| BOOT 键 | GPIO0 | 开发板自带，无需接线。短按急停，长按 2s 解除闩锁 |

改引脚要同步改 `include/config.h` 和这张表，两处不一致比两处都错更难查。

传感器怎么接到行为上（接触、体动、静止暂停、DHT 不做熔断）见 [`src/sensors/sensor_logic.md`](src/sensors/sensor_logic.md)。

GPIO0 是 strapping 脚：**上电时按住会进下载模式**，那种情况下固件根本不会跑，
所以它不构成安全风险；运行期当普通输入读没有问题。

### 原按键开关器件：AO3400A 低边 N-MOS

2026-08-28 实测原按键：**关机态下两端电压约 3.7V**，短接即通路、电压归零。

3.7V 高于 3.3V，CD4066 整条路线因此作废。之前记的「情况 A / 情况 B」
（VDD 取 3V3 还是取原板电池 3.8V）现在都不用管了：

- 情况 A：3.7V 信号进 VDD=3.3V 的模拟开关，会经输入保护二极管往 ESP32 的 3V3 轨倒灌。
- 情况 B：VDD 抬到 3.8V 或 5V 就得从原板电池引线，控制端还要加电平转换管。

AO3400A 的源极就是地，**不需要任何供电轨，也不存在倒灌路径**，
栅极天然吃 3.3V 逻辑（Vgs(th) 典型 1.05V、最大 1.45V，3.3V 驱动完全饱和）。

| AO3400A 引脚（SOT-23） | 接到 | 备注 |
|---|---|---|
| 1（G 栅极） | GPIO7，串 1kΩ | **另加 47kΩ 下拉到 GND，必须先接** |
| 3（D 漏极） | 串 **10kΩ** 后接原按键触点 A | 3.7V 那一端；10kΩ 是限流，不可省 |
| 2（S 源极） | 原按键触点 B + 原电池负极 + ESP32 GND | 三方共地 |

原实体按钮保留并联，手按和软件按都能用。

#### 那颗 10kΩ 为什么是 10kΩ

原板的按键节点是高阻输入。两个实测数据点：串 1kΩ 短接能开机；
栅极浮空时 MOSFET 的 D-S 呈现约 200kΩ，**这也足以触发开机**。
后者反推原板上拉：按 CMOS 阈值约 0.3 × 3.8 = 1.14V，
要求 3.7 × 200 / (Rpu + 200) ≤ 1.14，得 Rpu ≥ 约 450kΩ，即兆欧量级。

于是 10kΩ 两头都占便宜：

- 功能侧：导通时节点电压 3.7 × 10 / 460 ≈ **80mV**，离 1.14V 阈值有 14 倍余量。
- 安全侧：支路电流封顶 3.7V / 10kΩ = **0.37mA**，比 CD4066 的 10mA 上限还硬。
- 不取更大值：47k → 350mV、100k → 670mV，余量迅速被吃掉，而限流收益为零。

±5% 碳膜、1/8W 即可（功耗 1.4mW）。因为 10kΩ 完全主导，
AO3400A 在 3.3V 栅压下按 2.5V 规格 Rds(on) < 48mΩ，相对 10kΩ 可忽略——选它的理由是没有供电轨，不是低阻。

**触点两端不要并电容。** 原板自己有消抖；并电容会拖慢边沿，
还会在断开瞬间往原板灌一下。CD4066 那颗 0.1µF 去耦是跟着器件走的，已随之删除。

#### 装配顺序（有过一次教训）

1. 先接 ESP32 GND 与原板电池负极共地，接好栅极的 47kΩ 下拉。
2. 再接 GPIO7 与串的 1kΩ，确认引脚默认输出低。
3. **最后**才接 D/S 到触点。

顺序反了会踩坑：栅极浮空时实测 D-S 约 200kΩ 半导通，一插上触点玩具就开机。
那不是坏管子，是浮空栅极的正常表现，先接下拉即可。

触点那两根线走焊接飞线，不要走面包板——这条支路对漏电流敏感。
接完先不接 GPIO，用杜邦线把栅极点到 3.3V 一秒确认能开机，再接 GPIO7。

### 原板按键语义（实测，不是假设）

| 动作 | 效果 |
|---|---|
| 长按约 1s | 电源**取反**：关机态 → 开机并停在第 1 档；开机态 → 关机 |
| 瞬时短接 | 档位循环，**仅开机态有效**，关机态短按毫无反应 |

这套语义描述的是原板行为，与用什么器件短接触点无关，所以从 CD4066 换到
AO3400A 没有改动任何时序常量。「长按 = 取反」而不是「长按 = 关机」，
这一条决定了 `ao3400.cpp` 的整个状态机：

- 上电**不发任何按键**。盲发一次"对齐用"的长按会把关着的玩具打开。
- 降档不靠短按绕一圈（中途必然经过原板第 9 档，也就是最强档），
  而是走「长按关机 → 长按开机 → 短按上去」，多花约 3 秒。
- `requestOffNow()` 在记录为关机时**什么都不按**，因为那一下长按会变成开机。

原板不回传任何状态，所以 `powered_` / `step_` 都是开环假设。
**关机是唯一可信的已知点**：一次把它关掉的长按之后，记录才重新对齐。

### 电机观测器与标定

`motor_sense.{h,cpp}` 用 MPU6050 判断原板此刻是不是在振动，用来补开环记录的漏洞：
有人手按实体键把玩具打开时，固件仍记为关机，停机指令就会因为「记录为关机」
而不发那次长按。

**硬边界：观测结果永不驱动按键。** 它只修正开环记录和报警，补救交给人。
让一个会被人体动作干扰的信号去按电源键，等于把「设备自己动起来」的权力交给噪声。
停机长按发出后若仍观测到振动，固件保持白灯、置遥测 `flags` bit4、串口喊人，
**不自动补按**。

判据不能复用 `InsertInference::accel_var()`——那是加速度模长的窗口方差，
人拿起玩具和电机转起来都会把它抬高。这里用**一阶差分能量**：电机振动过了
DLPF 42Hz 仍有高频残留，在 12Hz 采样下是相邻样本间的无规则抖动，差分能量高；
人体动作是 1-3Hz 的平滑轨迹，方差可能很大但相邻样本差分很小。

阈值必须在实物上标定，出厂值是占位值，所以 `MOTOR_SENSE_ENABLED` 默认为 **0**——
此时 `MotorSense::state()` 恒返回 `kUnknown`，一行逻辑都影响不到，只每秒打一行
`[motor-cal] jerk=... var=...`。标定步骤：

1. 烧这版固件，串口连上。
2. 跑五种场景各约 10 秒，记下 `jerk` 的范围：关机静置、关机手持晃动、
   开机第 1 档静置、开机第 8 档静置、开机且手持晃动。
3. 取「关机手持晃动」的上界与「开机第 1 档静置」的下界之间，
   填进 `MOTOR_JERK_ON_MG2` / `MOTOR_JERK_OFF_MG2`（留滞回间距）。
4. 把 `MOTOR_SENSE_ENABLED` 置 1 重烧。

如果这两组数在 12Hz 采样下压根分不开，退路是给 `Mpu6050` 加短时高速突发采样
（临时切 DLPF 260Hz + rate 0，连读约 128 个样本），那是另一个任务。

### 两条通讯通道

默认 BLE，备用 WiFi WebSocket，**同一时刻只开一条**——ESP32-S3 只有一路
2.4GHz 射频，两栈共存要靠时分，12Hz 的上行会开始抖，而这条链路上跑着停机指令。

切换规则在 `main.cpp` 的 `maybeSwitchTransport()`：当前通道空闲超过
`NL_TRANSPORT_IDLE_SWITCH_MS`（20 秒）且另一条可用才切，切过去起不来就退回来。
没配 WiFi 凭据时永远待在 BLE。

**切换不重置安全状态。** 闩锁、档位、模式都跨传输保持：换一条线连上来不是
"新的一次会话"，更不是解除停机的理由。

鉴权与全部拒绝规则收在 `downlink_gate.{h,cpp}`，两条传输共用同一个实例类型。
这是刻意的：规则抄成两份之后，只改了一边的修补会让另一条链路变成弱点，
而攻击者只需要弱的那条。

WiFi 凭据不进仓库：

```bash
cp include/local_config.h.example include/local_config.h
# 填 SSID / 密码（必须 2.4GHz，ESP32-S3 不支持 5GHz）
```

`local_config.h` 已被 `.gitignore` 排除。不建这个文件也能正常构建，
只是 WiFi 通道不启用。协议细节见 [`../../protocol/wifi_ws.md`](../../protocol/wifi_ws.md)，
其中包含一条必须知道的限制：`ws://` 是明文，手机浏览器上
**Web Bluetooth 与 WiFi 通道不可能同时可用**，WiFi 通道以 Android 壳和桌面 Chrome 为准。

## 强度封顶是怎么实现的

协议 `NL_LEVEL_MAX = 8`，而原板有 9 档。**第 9 档在软件上不可达**，
这就是 90% 封顶在这套硬件上的物理落地方式，不是巧合也不是凑数。
不要为了"能不能再大一点"去改这个常量。

## 停机路径

停机有两个入口，执行体是同一段 `applyStopNow()`：

| 入口 | 触发 | 闩锁记的 alert |
|---|---|---|
| 远端 `stop` | 手机经 BLE / WebSocket 写 downlink | `safeword` |
| BOOT 键短按 | 板上按一下，松手在 600ms 内 | `estop` |

两者都不在主循环里排队：收到的那一行就直接调 `Ao3400::requestOffNow()`
和 `LedRing::renderSafewordNow()`，断电与灯变白是同一时刻发生的。

链路断开也归零：手机是唯一的指令来源，连接一断就没有任何东西能再降档，
所以断连的默认行为必须是停下来。这一条与双板时期不同——那时 K10 上还有
摇杆和屏幕可以本地控，断连不停机是合理的；现在本板的本地入口只能停不能开。

### 恢复只有一条路

闩锁之后**不会自动恢复，也不能远程恢复**。唯一的解除途径是
**长按板上的 BOOT 键 2 秒**（`NL_BOOT_RESUME_HOLD_MS`）。

这条不变量不是靠"各处记得过滤 `resume`"来保证的，而是靠代码里不存在那条路径：

- `SafetyGovernor::onCommand` **没有** `NL_CMD_RESUME` 分支，收到就直接返回。
- `clearLatch()` 全工程只有 `main.cpp` 的 `pollBootKey()` 一处调用。
- 传输层额外拒绝 `resume` 并记 `bad_cmd`，但那只是给 App 的反馈，不是防线本身。

双板时期这条路在 K10 上（板载 A+B 双键），K10 删除后落到本板的 BOOT 键。
中间 600ms～2000ms 是刻意留空的死区：不这样做，一次"想停机但手慢了"
的按压会变成一次恢复。

要求物理在场是刻意的：用户喊过停之后设备自己重新动起来，
是这个产品最坏的失败模式，不该由软件单方面决定。
