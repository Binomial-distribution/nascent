# 玩具侧传感器使用逻辑（验证期）

权威口径在 `docs/architecture/产品架构.md`。本文件只说明固件怎么把三颗传感器接到行为上，避免联调时各写一套。

| 传感器 | 做什么 | 绝不做什么 |
|---|---|---|
| FSR402 | 贴合（`contact`）+ 1–2Hz 节律提取 | 高潮检测、医疗结论 |
| MPU6050 | 体动/静止、与压力一起推断使用状态；静止 ≥30s 暂停 | 单独把「有加速度」判成在使用中 |
| DHT11 | 环境温湿度，上行给 App 看 | 过温熔断（那是量产接触 NTC） |

## 使用状态（insert_state）

三态：`unknown` / `not_inserted` / `inserted`。对外文案是「是否在使用中」。

- **IMU 未就绪**：不下结论，锁在 `unknown`，也不把全零加速度当成「静止」。没有六轴就没有体动证据。
- **inserted**：接触压力持续 + 明显体动，各满 `INSERT_CONFIRM_MS`。
- **not_inserted**：无接触 + 静止，满 `INSERT_RELEASE_MS`。
- 其余（只压不晃、只晃不压、窗口没填满）：`unknown`。拿不准就不猜。

`unknown` 时安全总督禁止**自动**加档；人手动调档仍可。

## 静止暂停

静止且无接触累计 `NL_STILL_PAUSE_MS`（30s）→ 有效档位归零。`requested_level_` 保留，拿起后自动回到原档。这与断链不同：断链必须清请求档，否则重连会自己动起来。

## 节律

FSR 带通后的 1–2Hz 只写入遥测 `press_rhythm_mhz`，不驱动档位、不停机。JSON 上行目前没有这个字段（契约未列），联调页用原始 ADC 对照接触阈值。
